Track your parcels from the Austrian Post (Österreichische Post) in Home Assistant
and redirect deliveries to a drop-off place, a neighbour, a post office or a parcel
locker — the things you would otherwise do in the "Post" app.

## Features

- Sign in with your post.at account (e-mail and password, with a browser fallback for MFA and other prompts).
- Sensors for incoming, outgoing and ready-for-pickup shipments.
- One sensor per active shipment with its current tracking state, sender, estimated delivery and redirection.
- A `post_at_shipment_updated` event whenever a shipment changes its tracking state.
- Actions to redirect shipments, reset redirections, add, remove and rename shipments, query redirection
  options and track any shipment by its number.
- Re-authentication flow, options for the polling interval, and diagnostics with personal data redacted.

Built on the [`post-at-lib`](https://pypi.org/project/post-at-lib/) Python library
([source](https://github.com/ch-rit/post_at_lib)), which is just as unofficial.

## Requirements

- Home Assistant **2026.8** or newer (tested with 2026.10).
- An account for the Österreichische Post app / post.at ("Post Login").
- Internet access from Home Assistant (cloud polling).

## Installation

### HACS (custom repository)

1. Open **HACS** in Home Assistant.
2. Open the three-dot menu in the top right and select **Custom repositories**.
3. Add `https://github.com/ch-rit/ha-post-at` with type **Integration**.
4. Search for **Österreichische Post**, open it and select **Download**.
5. Restart Home Assistant.

### Manual

1. Download the [latest release](https://github.com/ch-rit/ha-post-at/releases) (or clone this repository).
2. Copy `custom_components/post_at` into the `custom_components` folder of your Home Assistant
   configuration directory, so that you end up with `<config>/custom_components/post_at/manifest.json`.
3. Restart Home Assistant.

## Configuration

Go to **Settings → Devices & services → Add integration** and search for **Österreichische Post**.

### Sign in with e-mail and password

Enter the e-mail address and password of your Post account. The integration signs in once, stores the
resulting session and forgets the password. Each account can be added only once; you can add several
different accounts.

### Browser sign-in (fallback)

If the Post login asks for more than e-mail and password — for example multi-factor authentication or
new terms of use — the password sign-in cannot continue and the flow switches to a browser sign-in:

1. Open your browser's developer tools (<kbd>F12</kbd>) and switch to the **Network** tab
   (enable **Preserve log** / **Persist logs**).
2. Open the sign-in link shown in the dialog and complete the login there, including any MFA step.
3. At the end the browser tries to open a URL like
   `msal228c4360-…://at.post.app/auth?code=…` and fails, because that address is meant for the Post app.
   That is expected.
4. Find that URL in the Network tab: select the last request to the Post login (a redirect, status `302`)
   and copy the value of the **Location** response header. Depending on the browser it may also be shown
   in the address bar or on the error page.
5. Paste the complete URL (starting with `msal228c4360-`) into the **Redirect URL** field and submit.

The link is valid for a single attempt. If it fails, restart the flow to get a new one.

### Options

Select **Configure** on the integration entry to change:

| Option | Default | Range | Description |
| --- | --- | --- | --- |
| Update interval (`scan_interval`) | 15 min | ≥ 5 min | How often the shipment list is fetched. |
| Keep delivered shipments (`keep_delivered_days`) | 3 days | 0–30 days | How long a per-shipment sensor stays after delivery. |

## Entities

Each Post account is a device with the account-wide sensors. Every tracked parcel gets its own device
below it, named after the parcel's title, the sender or the tracking number (renaming the shipment
renames the device).

**Account device**

| Entity | State | Attributes |
| --- | --- | --- |
| Incoming shipments | Number of incoming shipments not yet delivered | `shipments`: list of `tracking_number`, `title`, `sender`, `state` (see below), `state_text`, `last_update`, `estimated_delivery` |
| Outgoing shipments | Number of outgoing shipments not yet delivered | `shipments` (same as above) |
| Ready for pickup | Number of undelivered shipments waiting for pickup at a post office or parcel locker | — |

**Parcel device**

| Entity | Exists for | State | Attributes |
| --- | --- | --- | --- |
| Status (sensor) | Every parcel | Tracking state (see below) | `tracking_number`, `sender`, `title`, `direction` (`incoming`/`outgoing`), `state_key` (raw Post state), `state_text`, `last_event_description`, `last_event_timestamp`, `estimated_delivery`, `delivery_type`, `weight`, `redirection` (`place`, `neighbor`, `post_office`, `parcel_locker` or empty) |
| Delivery option (select) | Incoming parcels not delivered yet | Standard delivery or a drop-off place, see [Redirecting from the UI](#redirecting-from-the-ui) | `unavailability_reasons` (per redirection type, e.g. `PLACE: [SIGNATURE]`), `redirect_possible` |
| Pickup location (select) | Incoming parcels not delivered yet | The post office or parcel locker the parcel is redirected to, if any | — |

Parcel devices are created for every shipment that is not delivered yet, or that was delivered within
the last `keep_delivered_days` days. Once a parcel is delivered its selects are removed; once it drops out
completely the device is removed together with its entities. The Status sensor keeps the entity id of
the per-shipment sensor of earlier versions.

The Status sensor's state is an enum of the Post tracking states (translated in the UI):

| State | Meaning |
| --- | --- |
| `aviso` | Announced by the sender, not yet handed to the Post |
| `delivery_hand_over` | Handed over to the Post |
| `in_distribution` | In the distribution network |
| `in_delivery` | Out for delivery |
| `delivered` | Delivered |
| `unknown` | Any state the integration does not know (yet); the raw value is in the `state_key` attribute |

## Events

### `post_at_shipment_updated`

Fired when a shipment's tracking state changes between two updates. It is not fired for the very first
update after Home Assistant starts or the integration is set up.

| Field | Description |
| --- | --- |
| `tracking_number` | Tracking number |
| `title` | Title you gave the shipment (may be empty) |
| `sender` | Sender name (may be empty) |
| `old_state` | Previous state, e.g. `in_distribution` |
| `new_state` | New state, e.g. `in_delivery` |
| `state_text` | Human-readable status text from the Post |
| `direction` | `incoming` or `outgoing` |

Example automation — get a notification when a parcel is out for delivery:

```yaml
alias: Parcel out for delivery
triggers:
  - trigger: event
    event_type: post_at_shipment_updated
    event_data:
      new_state: in_delivery
      direction: incoming
actions:
  - action: notify.mobile_app_my_phone
    data:
      title: "📦 Parcel out for delivery"
      message: >-
        {{ trigger.event.data.title or trigger.event.data.sender or trigger.event.data.tracking_number }}:
        {{ trigger.event.data.state_text }}
```

## Redirecting from the UI

The selects on a parcel device let you redirect incoming parcels without writing an action — on the
device page, in a dashboard tile, or as a `select.select_option` action in automations.

**Delivery option** offers:

| Option | Meaning |
| --- | --- |
| `standard` | Standard delivery; selecting it cancels the current redirection |
| `front_door` | Leave it in front of the house door (`Vor_Haustüre`) |
| `apartment_door` | Leave it in front of the apartment door (`Vor_Wohnungstüre`) |
| `mailbox` | Leave it on or under the mailbox (`AufOderUnter_Briefkasten`) |
| `garage` | Leave it in the garage (`In_Garage`) |

The drop-off places are only offered while the Post allows a place redirection for the parcel
(see the `unavailability_reasons` attribute otherwise). A few more values only appear when such a
redirection is already active, for example set in the Post app or with an action, and cannot be chosen
here: `drop_off_place` (a drop-off place whose exact location is not known to Home Assistant),
`neighbor`, `post_office` and `parcel_locker`. Choose `standard` to cancel them.

**Pickup location** lists the post offices and parcel lockers the Post offers for the parcel, for example
"Post office: …" or "Parcel locker: …", or "Nearest post office" / "Nearest parcel locker" when the Post
does not name a branch. It is unavailable while neither is possible.

Handing a parcel to a neighbour and "another place" with a free-text description (`sonstige`) need more
input, so they stay available through [`post_at.redirect_shipment`](#post_atredirect_shipment) only.

> [!CAUTION]
> Redirects and redirect resets — from the selects as well as from the actions — have only been tested
> against a mocked API so far, not against the live Post service. Other account actions (such as renaming
> a shipment) have been verified live. Check the result in the Post app after your first redirect.

## Actions

All actions that work on your account accept an optional `config_entry_id`. It is only required when you
have configured more than one Post account. For the common redirects you can also use the selects
described in [Redirecting from the UI](#redirecting-from-the-ui); the actions remain for automations and
for redirects the selects do not cover (neighbour, other place with a description, a specific branch key).

### `post_at.redirect_shipment`

Redirect an incoming shipment. Which `target` is possible depends on the shipment; check with
[`post_at.get_redirection_options`](#post_atget_redirection_options) first.

| Field | Required | Description |
| --- | --- | --- |
| `tracking_number` | yes | Tracking number of the shipment |
| `target` | yes | `place`, `neighbor`, `post_office` or `parcel_locker` |
| `place` | for `place` | Drop-off place: `Vor_Haustüre`, `Vor_Wohnungstüre`, `AufOderUnter_Briefkasten`, `In_Garage` or `sonstige` |
| `description` | no | Free-text note for the carrier (`place` only; useful with `sonstige`) |
| `first_name`, `last_name`, `street` | for `neighbor` | The neighbour who accepts the parcel |
| `house_number`, `door` | no | The neighbour's house number and door (`neighbor` only) |
| `branch_key` | no | Branch to deliver to (`post_office` / `parcel_locker`); defaults to the branch the Post offers |

Leave it in front of the apartment door:

```yaml
action: post_at.redirect_shipment
data:
  tracking_number: "1234567890123456789012"
  target: place
  place: Vor_Wohnungstüre
```

Leave it somewhere else, with a description:

```yaml
action: post_at.redirect_shipment
data:
  tracking_number: "1234567890123456789012"
  target: place
  place: sonstige
  description: "Behind the garden gate, next to the bins"
```

Hand it to a neighbour:

```yaml
action: post_at.redirect_shipment
data:
  tracking_number: "1234567890123456789012"
  target: neighbor
  first_name: Maria
  last_name: Muster
  street: Musterstraße
  house_number: "12"
  door: "4"
```

Send it to a post office:

```yaml
action: post_at.redirect_shipment
data:
  tracking_number: "1234567890123456789012"
  target: post_office
```

Send it to a parcel locker:

```yaml
action: post_at.redirect_shipment
data:
  tracking_number: "1234567890123456789012"
  target: parcel_locker
```

### `post_at.reset_redirection`

Cancel a redirection you set before.

```yaml
action: post_at.reset_redirection
data:
  tracking_number: "1234567890123456789012"
  target: place
```

### `post_at.get_redirection_options`

Returns which redirections are available for a shipment (and why not), plus the known drop-off places.
This action only returns data, so call it with a `response_variable`:

```yaml
action: post_at.get_redirection_options
data:
  tracking_number: "1234567890123456789012"
response_variable: redirection
```

The response contains `options` — one entry per redirection type with `type` (`PLACE`, `NEIGHBOR`,
`POST_OFFICE`, `PARCEL_LOCKER`), `state` (`ENABLED`, `DISABLED` or `LOCKED`), `current` (whether this is
the redirection currently set) and `unavailability_reasons` (for example `SIGNATURE`, `CASH_ON_DELIVERY`
or `ACTIVE_REDIRECTION`) — and `places`, a list of drop-off places with `key` and `text`. You can try it
in **Developer tools → Actions**.

Example: redirect to the front door only when the Post allows it.

```yaml
sequence:
  - action: post_at.get_redirection_options
    data:
      tracking_number: "{{ tracking_number }}"
    response_variable: redirection
  - condition: template
    value_template: >-
      {{ redirection.options | selectattr('type', 'eq', 'PLACE')
         | selectattr('state', 'eq', 'ENABLED') | list | count > 0 }}
  - action: post_at.redirect_shipment
    data:
      tracking_number: "{{ tracking_number }}"
      target: place
      place: Vor_Haustüre
```

### `post_at.add_shipment`

Add a shipment to your account, as incoming (default) or outgoing (`outbound: true`).

```yaml
action: post_at.add_shipment
data:
  tracking_number: "1234567890123456789012"
  outbound: false
```

### `post_at.remove_shipment`

Remove a shipment from your account. Use the same `outbound` value it was added with.

```yaml
action: post_at.remove_shipment
data:
  tracking_number: "1234567890123456789012"
  outbound: false
```

### `post_at.rename_shipment`

Give a shipment a title (this also renames its sensor).

```yaml
action: post_at.rename_shipment
data:
  tracking_number: "1234567890123456789012"
  title: New headphones
```

### `post_at.track_shipment`

Look up any shipment by tracking number with the public Post tracking — it does not have to be in your
account and needs no login (so it takes no `config_entry_id`). Returns the tracking result with
snake_case field names, or `{}` for an unknown number, so use a `response_variable`:

```yaml
action: post_at.track_shipment
data:
  tracking_number: "1234567890123456789012"
response_variable: tracking
```

```yaml
# e.g. in a script after the call above
- action: notify.mobile_app_my_phone
  data:
    message: "{{ tracking.tracking_number }}: {{ tracking.latest_event.description }}"
```

## Diagnostics

On the device or integration page select **Download diagnostics**. Session tokens, names, addresses and
tracking numbers are redacted, but please still look through the file before attaching it to an issue.

## Troubleshooting

- **"Re-authentication required"**: The Post session expired or was revoked (for example after signing
  out of all devices or changing your password). Open the repair/re-authentication notification and sign
  in again; the browser fallback is available here too. Refresh tokens are single-use and rotate on every
  refresh, so restoring an old backup or running the same account in two Home Assistant instances can also
  log you out.
- **MFA or "interaction required"**: Use the browser sign-in described above. Make sure you copy the full
  `msal228c4360-…://at.post.app/auth?code=…` URL, including the `code` parameter.
- **A redirection fails**: Check `post_at.get_redirection_options`. Many shipments (signature required,
  cash on delivery, already redirected, already out for delivery) cannot be redirected.
- **Debug logging**:

  ```yaml
  logger:
    default: warning
    logs:
      custom_components.post_at: debug
      post_at: debug
  ```
